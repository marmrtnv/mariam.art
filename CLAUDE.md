# CLAUDE.md — гайд для AI-агента

Персональная галерея работ Мариам Мартыновой. Astro static → GitHub Pages.
Английский интерфейс, светлая тема. Человеческий гайд — в `README.md`.
Здесь — модель данных, процесс и грабли.

## Архитектура

- В репозитории лежат сами картинки (`src/assets/photos/<slug>.jpg`, до 3840px) и метаданные
  (`src/content/photos/<slug>.yaml`). Сборка идёт в CI, доступа к машине автора там нет —
  поэтому всё нужное для сайта должно быть закоммичено.
- `astro:assets` генерит адаптивные WebP: сетка ~320–960px, фуллскрин 2560.
- Сайт пока публикуется по адресу `marmrtnv.github.io/mariam.art/`, отсюда `base: '/mariam.art'`
  в `astro.config.mjs`. **Из-за `base` все внутренние ссылки и пути к файлам из `public/`
  обязаны строиться через `import.meta.env.BASE_URL`** — абсолютный `/about` сломается.
  Ассеты, импортированные из `src/` (шрифты, картинки), Vite переписывает сам.

## Модель данных (YAML)

```yaml
title: ""                  # необязательно
image: my-work.jpg         # имя файла в src/assets/photos
src: "original.jpg"        # имя исходника, проставляет ingest — провенанс
date: 2026-03-14           # из EXIF (DateTimeOriginal/CreateDate), иначе mtime файла
tags: [painting, abstract] # ТЕМЫ из src/themes.json
favorite: false            # флаг фильтра ★ Favorites
rating: 5                  # опционально, не используется на сайте
```

**Темы** — единый источник `src/themes.json` (ключ → подпись). Оттуда их берут и галерея,
и `make-final-picker.mjs`, и `apply-final.mjs`. Добавляешь тему — правишь только этот файл.
Теги, которых нет в `themes.json`, в фильтры не попадут.

## Как каталогизировать новые работы (роль Claude)

После `npm run ingest` у новых записей `tags: []`. Нужно:
1. Посмотреть каждую новую картинку (Read по `src/assets/photos/<slug>.jpg`).
2. Назначить 1–3 темы из `src/themes.json`, нижний регистр.
3. Вписать `tags:` в YAML, затем `npm run lqip` и `npm run build`.

## Скрипты

| команда | что делает |
|---|---|
| `npm run ingest` | `inbox/` → сжатие до 3840px + YAML-заготовка, дата из EXIF |
| `npm run lqip` | blur-up превью всех мастеров → `src/lqip.json` |
| `npm run picker -- <папка>` | HTML-пикер для отбора картинок из любой папки |
| `npm run final-picker` | HTML-пикер по уже добавленному каталогу: отсев + правка тем |
| `npm run apply-final <json>` | применить решения финального пикера (удалить/перетегировать/★) |

## Пикер для отбора (многоразовый тул)

`npm run picker -- <папка|путь>` — генерит самодостаточный HTML `pickers/<label>.html`
(миниатюры base64, открывается двойным кликом, без сервера). Клик по картинке — полноэкранный
просмотр оригинала через `file://`; галочка в углу плитки — выбрать; в просмотре **S/пробел** —
выбрать/снять, **←/→** листать, **Esc** — закрыть. Выбор хранится в localStorage,
«Copy selected» / «Download .txt» отдают пути.

## Финальный пикер (отсев + теги перед деплоем)

`npm run final-picker` → `pickers/final.html` по текущему каталогу. В нём:
- **🗑** (во фуллскрине `X`) — пометить на удаление; **★** (`P`) — избранное; `U` — снять пометки;
- чипсы тем под картинкой и во фуллскрине — клик добавляет/снимает тему;
- фильтры вида: Все / Останутся / К удалению / ★ Избранные / Без тегов / Изменённые.

**Download** → `final-decisions.json`, применить: `npm run apply-final final-decisions.json`,
затем `npm run lqip && npm run build`.

**Грабли:** состояние пикера живёт в localStorage по ключу `KEY` (`mariam-final-vN`
в `make-final-picker.mjs`). После применённого прохода, когда перегенеришь пикер для следующего,
**бампни `KEY`** (v1→v2…) — иначе старые правки из localStorage перебьют свежий YAML.

## Грабли (проверено болью)

- **`base` и абсолютные пути**: внутренние ссылки (`/about`) и файлы из `public/` не переписываются
  автоматически — только через `import.meta.env.BASE_URL`. Шрифты специально лежат в
  `src/styles/fonts/` и подключаются относительным `url("./fonts/...")`, чтобы Vite сам их
  разрешил с учётом `base`; в `public/` их класть не надо.
- **`.card[hidden]`**: правило `.card{display:block}` перебивает UA-стиль `[hidden]{display:none}`
  (равная специфичность) — нужен явный `.card[hidden]{display:none}`, иначе фильтры «не фильтруют».
- **Masonry** — абсолютное позиционирование по `data-ar`; раскладку (`layout()`) дёргать и на
  `resize`, и в конце `apply()` (смена фильтра). DOM-порядок = хронологии, не ломать
  (от него зависят фильтр и лайтбокс).
- **Фуллскрин**: на навигации держим предыдущий резкий кадр (без блюра). Не возвращать blur-up
  в лайтбокс — мылит при листании.
- **Одинаковые имена файлов** дают одинаковый slug: `ingest` разруливает суффиксом `-2`,
  но лучше давать исходникам осмысленные имена — slug виден в адресе (`#slug`).

## Деплой

`.github/workflows/deploy.yml` собирает (`withastro/action`) и публикует (`deploy-pages`)
при push в `main`. Первая сборка долгая: все картинки пережимаются в WebP с нуля.
Переезд на домен `mariam.art` — раздел в `README.md`.
